## LaserFoundry 0.2.0

The second release of LaserFoundry, the open-source, clean-room laser engraver and cutter application in pure Rust. The headline
is **nesting**: pack a set of parts into your material in one step. There is also an undo history you can jump around in, a font
browser, more realistic time estimates, an application icon, a first direct link to Marlin controllers, and a round of fixes for
broken and hostile files.

> **This is still an early release.** The whole pipeline works end to end and is well tested, but **everything that talks to a machine
> has been tested only against the built-in simulator, not on real hardware.** Read
> [`docs/hardware-bringup.md`](https://github.com/Stitchwright/laserfoundry/blob/main/docs/hardware-bringup.md) before your first job: it covers safety, a laser-off motion test and
> first marks on scrap material. LaserFoundry is independent of, and unaffiliated with, other laser software vendors.

Each archive holds the desktop app and `laserfoundry-cli`. There is no build for Intel Macs yet. You can also try the design,
preview and G-code tools in your browser at https://stitchwright.github.io/laserfoundry/ (Web Serial machine control needs a
Chromium-based browser). Screenshots and a feature tour: https://stitchwright.github.io/laserfoundry/features/

### What's new

- **Nest parts into the material.** Select your parts and nest them into the bed: parts are turned to fit, kept apart by the gap
  you choose, packed around shapes already on the bed that you want left alone, and placed inside the holes of other parts when they
  fit. When a sheet is full, the rest go onto extra sheets, and a finer pass tries again for parts that did not fit the first
  time. The whole nest is one undo step. Nesting is approximate (a pixel-grid packer, not a proven-optimal one), so look at the
  result before you cut.
- **Undo history window.** See every step you have taken, by name, and jump to any of them.
- **Select by size.** Select all shapes within a width and height range, which is handy for finding stray specks after an import.
- **Font browser.** Browse the fonts you have and preview each one before using it.
- **More realistic time estimates.** The estimate and the preview now take corners at speed, following GRBL's published cornering
  model, instead of stopping dead at every corner. Estimates are usually shorter than in 0.1.0. A new **Corner deviation** field
  next to Acceleration sets it (0.01 mm by default, as GRBL's `$11`); set it to 0 for the old behaviour.
- **Application icon.** The window, the Windows program and the macOS app now carry the LaserFoundry mark (a beam striking a cut
  line), drawn in code rather than from an image file.
- **Marlin controllers (experimental).** LaserFoundry can now connect to a Marlin-laser controller, not only produce G-code for
  one. It was written from Marlin's public documentation and has been tried only against a simulator. Stop sends `M410` then
  `M5`, and jobs end at the first error. Read the Marlin section of the bring-up guide before using it.
- **The same engine everywhere.** Nesting and the other new commands are available in the browser version, the command line
  and as tools for AI agents, as everything else is.

### Fixed

- **Crash on a DXF with a huge circle, arc or ellipse.** A circle of radius 1e300 (or an arc or ellipse of similar size) could use
  all the computer's memory and kill the program. Such shapes are now skipped instead.
- **SVG files with a vast amount of text** (millions of characters) could keep the program busy for minutes. SVGs with more than
  40,000 bytes of text are now refused with a message saying to convert the text to paths first.
- The command line's `info` no longer prints `-0` for the length of an empty drawing.
- Messages shown while downloading fonts can now be translated.
- The tool column no longer wraps names such as "Rectangle", and now widens for longer translated names.

### Security and dependencies

- Updated the certificate-checking libraries (`rustls-webpki` and `webpki-roots`) after two published advisories
  (RUSTSEC-2026-0382 and RUSTSEC-2026-0381, about distrusted intermediate certificates). They sit under the optional HTTPS
  connections (the AI service and the font download); 0.1.0 shipped with the older versions. Also replaced a withdrawn
  (yanked) clipboard library version.
- The interface toolkit (egui and eframe) is updated to 0.37 and the HTTP client (ureq) to 3.5.0.
- An end-to-end regression suite now runs the real command-line program on many inputs and compares the G-code it makes
  byte for byte, and checks that broken files, extreme values and every command with no parameters give an error rather than a crash.

### Upgrading from 0.1.0

Project files from 0.1.0 open unchanged. The only visible difference is that time estimates are shorter (see above).

### Known limits

- **Not run on real hardware.** Every machine feature is verified against the simulator and the controllers' public documentation
  only. Please report what you find; the app can save a machine report (**Laser → Save machine report**) with nothing private in it.
- **Other controllers:** the Marlin-laser and Smoothieware support was written from public documentation and is untested on
  hardware. There is no Ruida support.
- **Signing:** the signed Windows and macOS builds have not yet been checked on a fresh machine, so the SmartScreen and
  Gatekeeper first-run experience is unconfirmed.
- **AI:** a signed-in request against the live account service has not been tried end to end, and the prompts have not been
  tuned from real use.
- **Scope:** this covers a fraction of what established laser software does.
  [`docs/target-app-parity.md`](https://github.com/Stitchwright/laserfoundry/blob/main/docs/target-app-parity.md)
  is an honest self-assessment and [`docs/gaps.md`](https://github.com/Stitchwright/laserfoundry/blob/main/docs/gaps.md) is the ranked work list.
