## LaserFoundry 0.2.1

A small update to 0.2.0: you can now name the design you send to MakerFoundry, there are two new links in the Help menu, a job-size
safety limit is tightened, and the libraries that read SVG files and shape text are updated.

> **This is still an early release.** Everything that talks to a machine has been tested only against the built-in simulator, not
> on real hardware. Read
> [`docs/hardware-bringup.md`](https://github.com/Stitchwright/laserfoundry/blob/main/docs/hardware-bringup.md) before your first job: it covers safety, a laser-off motion test and
> first marks on scrap material. LaserFoundry is independent of, and unaffiliated with, other laser software vendors.

### Download

| Platform              | File                            | Notes                                                         |
|-----------------------|---------------------------------|---------------------------------------------------------------|
| Windows (x64)         | `laserfoundry-windows-x64.zip`  | Signed with Azure Trusted Signing                             |
| macOS (Apple silicon) | `laserfoundry-macos-arm64.zip`  | Signed with a Developer ID certificate, notarized and stapled |
| Linux (x64)           | `laserfoundry-linux-x64.tar.gz` | Not signed; needs the usual X11 or Wayland libraries          |

Each archive holds the desktop app and `laserfoundry-cli`. You can also try LaserFoundry in your browser at
https://stitchwright.github.io/laserfoundry/ and see a feature tour at https://stitchwright.github.io/laserfoundry/features/

### What's new

- **Name your design for MakerFoundry.** **File › Publish to MakerFoundry…** now has a Name field. The draft on MakerFoundry takes its
  title from it (letters, digits, spaces, `-` and `_`; anything else becomes `_`; at most 60 characters). Leave it empty and the
  publish is refused with a message, so a draft is never created with a placeholder title.
- **Opening designs from MakerFoundry works with real designs.** Checked in the browser version against two published test
  designs, one SVG and one DXF: the file name comes from MakerFoundry's answer, and the drawing opens at its true size.
- **Help links.** **Help › MakerFoundry on YouTube…** opens the MakerFoundry channel, and **Help › Support the Project…** opens a
  Buy Me a Coffee page if you want to chip in. It is optional and unlocks nothing. Nothing is sent when you click either.

### Fixed

- **The job-size limit now counts every pass.** A layer set to many passes could slip past the limit on the number of moves in a
  job and make the program run out of memory while it planned the cut; the limit now counts moves times passes.

### Dependencies

- Updated the SVG reader (`usvg` 0.49), the text shaper (`harfrust` 0.15), the font reader (`skrifa` 0.49) and the XML reader
  (`roxmltree` 0.21.2), plus two CI actions (Windows signing, build cache). SVG import and text are covered by the test suite
  but have had less real-world use with these versions: please report anything that imports differently from 0.2.0.

### Upgrading from 0.2.0

Project files open unchanged.

### Known limits

- **Not run on real hardware.** Every machine feature is verified against the simulator and the controllers' public documentation
  only. Please report what you find; the app can save a machine report (**Laser → Save machine report**) with nothing private in it.
- **Other controllers:** the Marlin-laser and Smoothieware support is untested on hardware. There is no Ruida support.
- **Signing:** the signed Windows and macOS builds have not yet been checked on a fresh machine, so the SmartScreen and
  Gatekeeper first-run experience is unconfirmed.
- **Scope:** this covers a fraction of what established laser software does.
  [`docs/target-app-parity.md`](https://github.com/Stitchwright/laserfoundry/blob/main/docs/target-app-parity.md)
  is an honest self-assessment and [`docs/gaps.md`](https://github.com/Stitchwright/laserfoundry/blob/main/docs/gaps.md) is the ranked work list.
